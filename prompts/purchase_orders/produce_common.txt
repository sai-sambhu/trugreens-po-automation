===========================================================
PRODUCE RULES (fruits, veggies and leafy lists)
===========================================================
The record is usually a WhatsApp-style message (pasted text, or a screenshot/photo/PDF of one) and may hold several delivery_date+vendor blocks.

VENDORS
Exactly 3 valid vendor values: "Kanchana Vegetables", "Kanchana Fruits", "Manoj". Map the input to one of them. Never output plain "Kanchana". If the message says "fruits" or "vegetables"/"veg", use that. If it says only "Kanchana", decide from the items: all vegetables/greens -> "Kanchana Vegetables"; all fruits -> "Kanchana Fruits". If one Kanchana block mixes both, split it into two blocks (one per vendor, same date) and add a warning. If it does not clearly match any, set "vendor": null and say in "warnings" what the input said.

UNIT HANDLING
An item's unit is fixed by the list's third column "Count or Weight", never by its name and never by what sounds natural: Count -> "pc", Weight -> "kg". Ignore "1 Pc", "1 Kg", "250g" written inside an item name.

Grams are not a different unit: for a Weight item, "450 gram" / "450 gm" / "450g" is 0.45 kg (grams / 1000). Convert it directly, with no override, no warning, and never put it in unmatched_items. For a Count item, grams cannot become pieces unless the item has a rule in MANUAL CONVERSION OVERRIDES: put that line in unmatched_items instead of guessing.

A decimal quantity (25.5 kg) is normal for Weight items and never a reason to invent a piece conversion.

When the message unit differs from the item's unit (for example "4kg" for a Count item, or "10 pc" for a Weight item):
a. If THIS EXACT item is in MANUAL CONVERSION OVERRIDES below (never reuse one item's factor for another, even a similar one), convert with that factor and give the quantity in the item's unit. No warning needed: the page records the conversion. This covers kg <-> pieces ("1 kg = 25 pc") and container units such as box, bag or gala ("1 box = 23 kg": 2 boxes of Tomatoes = 46 kg).
b. If there is NO rule, do NOT estimate or invent a factor and NEVER just relabel the number ("5kg" of a Count item is NOT "5 pc", "6pc" of a Weight item is NOT "6 kg"). Put the line in "unmatched_items" with its line_total and a reason such as "Unit mismatch: <item> is Count (pc) in the DB but the message gave kg, and there is no conversion rule."
CHECK THE MESSAGE UNIT FIRST. If it already equals the item's unit (a Count item written in pc/pcs/pieces, a Weight item written in kg), copy the number exactly as written and apply NO override: "Spring onion 10 pc-50rs" -> 10 pc, "Lemon 100 pc" -> 100 pc. An override is used only when the message unit is the OTHER unit (kg for a Count item, pc for a Weight item) or a container word (box, bag, gala). Never multiply a number that is already in the item's own unit.

MANUAL CONVERSION OVERRIDES (the list-specific section below holds them). Line format: "- <exact item name> : <A> kg = <B> pc" or "- <exact item name> : <A> box|bag|gala = <B> pc|kg" ("7.8 kg = 10 pc" means 1 pc = 0.78 kg).

QUANTITY DERIVATION: when a line gives no usable quantity
Derive it by the rules below and say so in "warnings" (it is inferred). Fixed-weight box items: trust a stated kg figure or box count. quantity = boxes x box weight when boxes are stated; = the stated kg when kg are given; = the weight of 1 box when neither is given (a line "Pomogranate -2400" -> 9 kg, warning "Pomogranate quantity assumed as 1 box x 9kg since only a line_total was given."). Box weights are in the list-specific section.
